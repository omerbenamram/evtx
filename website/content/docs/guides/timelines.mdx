---
title: Building a timeline
description: Put the $MFT, the change journal and event logs on one sorted timeline.
---

There are two ways to do this. `mactime` is the quick one when the `$MFT` is all you need. Sorting CSV rows from several sources takes a few more lines and puts files, journal records and events side by side.

## The file system, with mactime

```bash
mft_dump -o bodyfile '$MFT' > mft.body
mactime -b mft.body -d -y 2019-01-30T21:22:00..2019-01-30T21:26:00 | grep 'Documents/Misc'
```

`-o bodyfile` writes what The Sleuth Kit's `fls -m` writes: a line for each name and each data stream with the `$STANDARD_INFORMATION` times, and a line ending in `($FILE_NAME)` with the `$FILE_NAME` times. `mactime` rounds to seconds, and its four letters are modified, accessed, changed (the MFT record) and born.

In Python, `PyMftParser("$MFT").entries_bodyfile()` yields the same lines. It is in the repository and ships with the next release of the `mft` package.

## Several sources, sorted

Write each source as rows of `time, source, what, path`, then sort them all together:

```bash
mft_dump -o jsonl '$MFT' | jq -r 'select(.full_path) | . as $e
  | first(.attributes[] | select(.header.type_code == "FileName"))
  | [.data.created, "mft", "created", $e.full_path] | @csv' > mft.csv

mft_dump -o jsonl -m '$MFT' '$J' | jq -r 'select(.reason | test("CLOSE"))
  | [.timestamp, "usn", .reason, .full_path] | @csv' > usn.csv

LC_ALL=C sort mft.csv usn.csv > timeline.csv
grep 'Misc\\Method Route' timeline.csv | cut -c 1-140
```


The `$MFT` says `Method Route.jpg` was created at 21:22:24. The journal adds what the `$MFT` can't: the file was saved as `Method Route 2.jpg`, and renamed three minutes later.

Why this works without a real CSV sorter: every tool here writes UTC times in the same form, always with seven decimal places, so sorting the lines as bytes (`LC_ALL=C`) sorts them by time. Keeping only the journal records with `CLOSE` gives one row per action in place of one per step.

Event logs go in the same way:

```bash
evtx_dump -o jsonl Security.evtx | jq -r '.Event
  | [.System.TimeCreated["#attributes"].SystemTime, "evtx", .System.EventID, .EventData.TargetUserName // ""] | @csv' > evtx.csv
```

```text
"2016-07-08T18:12:51.7596409Z","evtx",4902,""
```

## Which timestamp is which

| Source | Field | It changes when | Trust |
| --- | --- | --- | --- |
| `$MFT`, `$STANDARD_INFORMATION` | `StandardInfo*` | the file is created, written, read or has its metadata changed | Any program can set these, so they are the first thing a timestomping tool changes. |
| `$MFT`, `$FILE_NAME` | `FileName*` | the file is created, renamed or moved | Windows sets them itself. Changing them takes raw disk access or a trick such as a rename after setting the others. |
| `$J` | `timestamp` | never: it is when the journal record was written | Good, and it comes with the reason for the change. |
| Event log | `TimeCreated` | never: it is when the event was logged | Good, but it follows the system clock, so look for clock changes (event 4616). |
